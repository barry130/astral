# 第四轮定向续审与公开回归边界

用户继续原对话并询问“还有其他的需要进一步吗”。沿用 [原授权](../2026-11-07/SPEC.md) 的确认问题直接修复、仅本地提交与外部副作用隔离边界。本轮增量固定起点为 `9679cec2082d905df96186748c7413d3b72c4b8b`，第三轮已冻结的审计资料保持原样。

- 合并消息模板：公开 `MessageTemplateService.save/list/delete` → 实际 MyBatis、隔离 H2 与 Spring 事务代理。观察勾选短信时必需的供应商映射、审核状态、渠道预配置、字段清空、改事件后的变量声明与失败回滚。通过公开列表和渠道服务详情读取持久化结果，不调用私有校验器或断言 wrapper 结构。
- 短信实际读取：公开 `SmsService.sendSystemAlert` → 实际模板查询/缓存与内存 SMS SPI，观察保存后的供应商编码和签名回退。供应商与日志边界隔离，不向真实收件人发送。
- 输入长度：使用同一公开保存边界与实际生成实体的 Bean Validation 约束，检查所选渠道的真实列宽。邮件及短信名称在已提交 Flyway DDL 中均为 64 字符；邮件 schema 的 128 属于元数据偏差，须对齐 64，而非当作已被数据库接受的上限。未勾选渠道不阻止保存。单渠道邮件入口采用实际 Controller、MockMvc 与 Bean Validation，观察超长字段在写入前被拒绝；框架校验测试不等于完整应用的 HTTP 鉴权验收。
- 相邻权限定义写入、注册器/目录缓存和单渠道邮件删除先作源码及实际调用方检查；通用 CRUD 调用本身不记为缺陷。有具体触发与观察边界才扩展回归。

这些边界继承 [既有测试约定](../2026-11-07/TEST-SEAMS.md) 和用户持续直接修复授权，不重复请求逐项批准。实施采用 tdd 的单一行为 RED → 最小修复 → GREEN。H2 仅证明持久化与事务语义，不能替代 PostgreSQL 并发锁、真实 HTTP 鉴权、浏览器或生产验收。本轮不执行浏览器诊断或外部 SMTP/SMS/模型调用。
