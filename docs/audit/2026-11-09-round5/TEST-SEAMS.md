# 第五轮管理写入口验证边界

沿用原 SPEC 的直接修复授权与用户“所有的自行决定，不需要问我”的持续指令。创建校验和局部写入复用已授权的公开 Controller / MockMvc → 实际 Bean Validation、Service、MyBatis、隔离 H2 边界；通过公开详情或列表观察保存结果与拒绝后的存量保留，不断言私有实现或 SQL wrapper 形状。

- 完整创建及完整表单更新：应在持久化前拒绝实际 DDL 不允许的缺失/超长值；同时保留数据库允许的边界值。
- 局部更新：仅校验实际提交且可写的字段，省略字段保留；用户资料不能因没提交密码被拒绝，角色元数据不能因没提交不可改编码被拒绝，菜单拖拽继续允许 sort/parentId 载荷。
- 列宽和必填规则依据实际已提交 Flyway DDL，先核对增量迁移，再修正 schema 并实际生成实体；不修改历史迁移。
- MockMvc 使用默认异常解析器，验证请求绑定与校验时机，不声称完整应用的 HTTP/body-code、权限或浏览器验收。外部发信仅使用实际服务的缓存方法，不调用 SMTP/SMS。

补充复用已授权的 Form 公开边界：实际 React DOM 挂载/卸载 `Form.Item`，通过 `validateFields`、字段错误和保留值观察条件分区、重新挂载及异步校验失效。jsdom 仅替代 DOM，不替代 React 或表单实现；不代表浏览器布局、IME、滚轮或跨标签验收。
