## 1. 为什么问题会反复暴露

1. **只修单个入口，没有核对同一业务的所有写入口。** Controller、Service、AI 工具、默认角色初始化、合并表单和列表开关可能操作同一组数据；一个入口有校验、锁或缓存失效，不代表其余入口具有同样保护。
2. **把表单语义交给 ORM 默认行为。** 整行回写、默认忽略 null、创建与局部修改共用必填规则，使省略字段、显式清空、敏感字段保护出现相互矛盾的结果。
3. **在事务外判断，或在提交前失效缓存。** 单次请求看似正确，遇到删除/分配交错、审批等待、热缓存重读时会留下悬空关联、覆盖新状态或继续使用旧权限。
4. **验证对象与实际运行对象不一致。** 生成实体与手工源码、测试构造器与 Spring 装配、H2 与 PostgreSQL 锁、HTTP 客户端与浏览器各有边界；编译、静态扫描和局部测试不能证明这些边界全部成立。
5. **证据缺少固定版本和执行范围时容易误判完成。** 旧 Surefire XML、继承的前端结果、被跳过的集成测试、未启动的页面，都需要独立标识，不能合并成一次“全通过”。
